# 发布检查表

当前是**本地发布准备**，不是可上传结论。旧开发历史和旧 `dist-review` 成品均不作为公开发布物。准备目录没有 Git 历史，不自动建立远程或上传。

- [ ] 核实在用图标的分发权利：作者已确认使用 GPT 生成，`assets/LICENSE.txt` 已记录来源与待核事项，但适用条款全文仍未核实；不得仅凭来源记录存在就认定授权审核通过。
- [x] 早期试用版本定为 `0.1.0-beta.57`：`package.json` 与 `package-lock.json` 顶层及根包的 `version` 已同步。首次定版时原开发仓有 57 个本地提交（含文档、整理等提交），所以取 57，**不代表 57 次发布**；之后按版本号递增，不是每次提交都发版。草稿 Release 只挂版本号、不附二进制，首次双包构建与实测完成前不算可下载版本。
- [ ] 在干净环境构建全部五个运行 helper，安装固定依赖，核对 gifenc 及 Electron/Chromium 许可。
- [ ] 对同一份公开源码同时构建安装版和免安装版；生成独立文件名、大小和 SHA-256。
- [ ] 核验实际解包文件与白名单、源文件哈希一致，五个 helper 均为 x64，不混入实验、用户数据或私人开发记录。
- [ ] 独立检查安装版和免安装版内载荷；不把旧审查包或仅 builder 成功当作通过。
- [ ] 在独立 Windows 测试环境验证安装、首次启动、截图、复制、保存、长图、GIF、退出、再次启动和卸载。
- [ ] 验证免安装外层 EXE 的自启路径、移动后的行为，以及安装版自启／卸载时的 Run 项；卸载默认保留个人设置与图片，不静默清除。

- [ ] 对最终同一份候选做独立审查，人工复核许可、隐私和打包证据，再授权上传。

## 本地准备与打包入口

`node scripts/prepare-public-source.cjs` 用白名单生成一个全新的 `review-source/` 候选目录和外置哈希清单。不复制 `.git`、node_modules、原生 EXE、历史开发记录、日志、私人截图、实验或备份；只纳入白名单里明确指定的两张 README 演示图。它是**待审核源码**，不是已可发布包。

`electron-builder.release.json` 用于公开双交付，与旧 `electron-builder.json` 本地审查配置分开。预检 `node scripts/release-preflight.cjs` 会在候选版本、许可证、图标记录、必需 helper 或依赖不齐时失败，不应绕过。

满足门禁并明确执行本地打包时，在干净候选目录内使用固定构建工具：

```powershell
$env:CSC_IDENTITY_AUTO_DISCOVERY='false'
npm exec --yes --package=electron-builder@26.18.0 -- electron-builder --config electron-builder.release.json --win nsis portable --x64 --publish never
```

该命令可能从网络下载固定构建工具或 NSIS 资源，不是离线构建。首次发布应记录实际工具、依赖和构建环境；不能把版本固定等同于所有构建输入已离线归档。

期望文件名：

- `Jiegetu-<version>-Setup-x64.exe`
- `Jiegetu-<version>-Portable-x64.exe`

安装器使用当前用户向导，允许选择目录；安装完成不自动启动。无代码签名时如实说明，不关闭系统安全功能。当前尚未实际构建或验证这些交付物。

## 公开仓库边界

保留运行源码、原生 C# 源码、构建/测试代码、锁文件、实际使用且授权明确的三个图标、两张经确认的 README 演示图、公共文档和许可。源码不包含安装时所需的预编译 helper；新检出先完成构建，再运行测试。

开发用的诊断启动入口（根目录 `启动截个图.cmd`、`启动截个图（后台）.vbs`、`scripts/diagnostic-launch.ps1`）和只测这些入口的 `test/diagnostic-launch*.test.cjs` 不进公开目录，只在本机保留，避免公开源码出现缺被测入口的测试；公开源码从 `npm start` 启动。运行时排障模块及其测试照常导出。

不要推送旧开发仓历史，不用改写现用仓来清历史。公开仓从审过的干净目录另建初始提交，旧仓和备份留在本地。首次提交与上传时重新检查最终目录，不能仅依赖一次关键词扫描。
